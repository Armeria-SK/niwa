# 承認付きフォーム送信

通常HTMLフォームの準備と、確定内容への承認を実装しています。実サービスへの送信・登録・購入は未実施です。

`browser_form_prepare` は最新画面の送信ボタン参照と、入力項目の参照・値を受け取ります。専用ブラウザーで通常フォームのURL・GET/POST・全送信項目を取り出し、送信せず返します。指定値は準備後に戻します。hidden項目と選択済みcheckbox、送信ボタンの名前/値も含みます。準備中は親側に通信を許可しません。

`browser_form_submit` はその内容を管理者の承認画面に提示して仕事を待機させます。完全な表示内容のhashと仕事内操作IDを保存し、管理者が表示版を承認した後、同じ操作だけを実行します。別内容・別操作は再承認が必要です。説明文だけの従来の `approval_request` では送信を許可しません。送信要求は他のツールと同じ応答に混ぜられません。

送信は本体の専用経路で行います。公開HTTPS・IPv4の宛先を検査してDNS結果へ接続を固定し、任意ヘッダー・Cookie・認証・proxyを受け取りません。GETはフォーム項目でqueryを置換し、POSTはURL encoded本文を使います。転送先へ自動で送り直しません。HTTP応答のstatusと短い本文は未信頼の結果として返し、購入や登録の成立そのものを保証しません。一般ブラウザーの画面遷移やログイン状態へは反映しません。

`runtime/forms.db` に操作hashと結果を保存し、送信前intentを永続化します。結果が不明なら自動再送せず確認待ちにします。通常backup外のjournalが失われた場合も、復元した古い仕事を推測で送信しません。

対象は認証不要の通常URL encodedフォームです。ファイル・passwordを含むフォーム、JavaScript独自の送信、ログインが必要な操作、iframe/shadow DOM内のフォームはこの経路では扱いません。必要な場合は管理者が専用の接続方式と資格情報の取扱いを用意します。宛先と項目は管理者が全部読める2000文字以内に制限し、大きい内容を省略して承認扱いにはしません。

人工モデル・実SQLite・IPC・専用Chromeで、準備時送信なし、元入力の復元、承認前送信なし、内容変更の再承認、実行一回、承認後再起動からの再開を検証しました。管理画面は1440/390幅で全内容の表示・折返し・同時二回clickでPOST一回を確認しています。これは実サービスでの操作成立や、実Ubuntuの隔離検証完了を意味しません。

フォームデータの取得は[FormDataの仕様説明](https://developer.mozilla.org/en-US/docs/Web/API/FormData/FormData)を参照しました。構築時のformdataイベントは発生し得ますが、submit/clickは実行せず、親プロセスはこの準備中のネットワーク要求を許可しません。
